# 法人AI ナレッジ検索システム改善プロンプト

## 概要

このプロジェクトは法人向けAIエージェントシステム「法人AI」のナレッジ検索機能を改善するタスクです。

現状の**Gemini File Search**ベースのRAGシステムに加えて、**Firestore Vector Search**を使った新しいRAGシステムを実装し、ABテストで精度を比較できるようにしてください。

---

## 現状の課題

### Gemini File Searchの問題点
- 返却チャンク数を制御できない（Geminiが勝手に決める）
- ページネーション不可（「次の10件」が取れない）
- 類似度スコアが取得できない
- リランキングのカスタマイズができない（ブラックボックス）
- 1クエリあたり最大5ストアまでの制限

### 要件
「全部のナレッジを見た上で、本当に関連するものを出す」ための検索精度向上

## 実装タスク

### 1. Firestore Vector Search の実装

新しいファイル `lib/firestore-vector-search.ts` を作成し、以下を実装：

```typescript
// 必要な機能
- createEmbedding(text: string): Promise<number[]>  // Gemini Embedding APIでベクトル生成
- storeDocument(doc: { id, content, embedding, metadata }): Promise<void>  // Firestoreにベクトル保存
- searchSimilar(query: string, options: { limit: number, threshold?: number }): Promise<SearchResult[]>  // 類似検索
- rerank(query: string, results: SearchResult[]): Promise<SearchResult[]>  // LLMベースのリランキング
```

#### Firestore Vector Searchの使い方

```typescript
import { FieldValue } from 'firebase-admin/firestore';

// ベクトル保存
await db.collection('knowledge_chunks').add({
  content: "ドキュメントの内容",
  embedding: FieldValue.vector([0.1, 0.2, ..., 0.3]),  // 768次元
  metadata: {
    documentId: "xxx",
    title: "油圧マニュアル",
    chunkIndex: 0
  },
  createdAt: new Date()
});

// 類似検索（find_nearest）
const queryEmbedding = await createEmbedding("油圧システムのメンテナンス方法");
const results = await db.collection('knowledge_chunks')
  .findNearest('embedding', queryEmbedding, {
    limit: 20,  // ← 自分で制御可能！
    distanceMeasure: 'COSINE'
  })
  .get();
```

#### Gemini Embedding API

```typescript
import { GoogleGenAI } from '@google/genai';

const ai = new GoogleGenAI({ apiKey: process.env.GEMINI_API_KEY });

async function createEmbedding(text: string): Promise<number[]> {
  const result = await ai.models.embedContent({
    model: 'gemini-embedding-001',
    contents: [{ parts: [{ text }] }],
  });
  return result.embeddings[0].values;
}
```

```typescript
export type RetrievalMethod = 'gemini_file_search' | 'firestore_vector';

export interface ABTestConfig {
  method: RetrievalMethod;
  // 将来的にはユーザーごとにランダム振り分けも可能に
}

export async function searchWithABTest(
  query: string,
  config: ABTestConfig,
  options: SearchOptions
): Promise<SearchResult> {
  if (config.method === 'gemini_file_search') {
    return searchWithGeminiFileSearch(query, options);
  } else {
    return searchWithFirestoreVector(query, options);
  }
}

// 両方の結果を取得して比較する関数
export async function compareRetrievalMethods(
  query: string,
  options: SearchOptions
): Promise<{
  geminiResults: SearchResult;
  firestoreResults: SearchResult;
  comparison: ComparisonMetrics;
}>;
```

## 注意事項

- Gemini Embedding APIは無料で使用可能
- Firestoreのベクトル次元は最大2048（gemini-embedding-001は768次元）
- find_nearestの最大limit は1000
- ベクトル検索ではリアルタイムリスナー非対応
- 既存のGemini File Search機能は維持し、ABテストで比較できるようにする

## 成功基準

1. Firestore Vector Searchで検索が動作する

3. 類似度スコアが取得できる
4. ABテストで両方の検索結果を比較できる
5. 既存機能が壊れない
