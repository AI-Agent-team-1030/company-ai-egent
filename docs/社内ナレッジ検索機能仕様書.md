# 社内ナレッジ検索機能 仕様書

> **目的**: 本ドキュメントは社内ナレッジ検索機能の技術仕様を記述したものです。
> UIリデザインやフロントエンド再構築時に、機能要件とデータフローを維持しながら新規実装を行うための参照資料として使用できます。

---

## 1. 機能概要

### 1.1 システム概要

社内ナレッジ検索は、Gemini File Search APIを核としたRAG（Retrieval-Augmented Generation）システムです。

**主な機能:**
- ドキュメントのアップロード・管理
- フォルダによる整理
- チャット時の自動ナレッジ検索
- 検索結果の引用表示

### 1.2 対応ファイル形式

| カテゴリ | 拡張子 |
|---------|--------|
| ドキュメント | `.pdf`, `.docx`, `.doc`, `.txt`, `.md` |
| スプレッドシート | `.xlsx`, `.xls`, `.csv` |
| プレゼンテーション | `.pptx`, `.ppt` |
| 画像 | `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp` |

## 2. データ構造

### 2.1 型定義

```typescript
// ドキュメント
interface KnowledgeDocument {
  id: string                    // Firestore ドキュメントID
  fileName: string              // Firebase Storage での保存ファイル名
  originalFileName: string      // 元のファイル名（表示用）
  geminiFileName: string        // Gemini File Search での内部ファイル名
  storeName: string             // 所属するFile Searchストア名
  folderId: string | null       // 所属フォルダID（ルートの場合はnull）
  fileUrl: string | null        // Firebase StorageのダウンロードURL
  mimeType: string | null       // MIMEタイプ
  createdAt: Date               // 作成日時
}

// フォルダ
interface KnowledgeFolder {
  id: string                    // Firestore ドキュメントID
  name: string                  // フォルダ名
  companyId: string             // 所属会社ID
  parentFolderId: string | null // 親フォルダID（1階層のみ使用）
  createdAt: Date
  updatedAt: Date
}

// File Searchストア情報
interface FileSearchStore {
  id: string
  storeName: string             // Gemini APIの内部識別子
  displayName: string           // ユーザー向け表示名
  companyId: string
  createdAt: Date
}

// 検索結果の引用情報
interface Citation {
  title: string                 // ドキュメント表示名
  uri: string                   // ファイルURLまたは参照URI
  text: string                  // 引用テキスト
  source: 'knowledge' | 'drive' | 'onedrive' | 'web'
  mimeType?: string
}

// アップロード処理状態
interface ProcessingStatus {
  [fileId: string]: {
    status: 'uploading' | 'processing' | 'completed' | 'error'
    progress: number            // 0-100
    message: string
  }
}
```

## 3. 機能詳細

### 3.1 ドキュメント管理

#### 3.1.1 アップロード処理フロー

```
[ファイル選択]
    │
    ▼
[1] File Searchストア取得/作成
    │   - 既存ストアがあれば取得
    │   - なければ createFileSearchStore() で新規作成
    │
    ▼
[2] Firebase Storageにアップロード
    │   - パス: knowledge/{companyId}/{timestamp}_{fileName}
    │   - ダウンロードURLを取得
    │
    ▼
[3] Gemini Files APIにアップロード
    │   - uploadFile(apiKey, buffer, fileName, mimeType)
    │   - geminiFileName を取得
    │
    ▼
[4] File Searchストアにインポート
    │   - importFileToStore(apiKey, storeName, geminiFileName)
    │   - インデックス作成（3秒待機）
    │
    ▼
[5] Firestoreにメタデータ保存
    │   - saveUploadedDocument()
    │
    ▼
[完了]
```

**進捗状態の遷移:**

| 段階 | 進捗率 | ステータス | メッセージ例 |
|------|--------|------------|--------------|
| 開始 | 10% | uploading | アップロード中... |
| Storage保存 | 30% | processing | ストレージに保存中... |
| Gemini送信 | 50% | processing | AIに送信中... |
| インデックス作成 | 70% | processing | インデックス作成中... |
| メタデータ保存 | 90% | processing | 保存中... |
| 完了 | 100% | completed | 完了 |
| エラー時 | - | error | エラーメッセージ |

#### 3.1.2 削除処理

```
[削除ボタンクリック]
    │
    ▼
[確認ダイアログ表示]
    │
    ▼
[Gemini Storageから削除]
    │   - deleteFileCompletely(apiKey, storeName, geminiFileName)
    │   - File Searchストアからも自動除外される
    │
    ▼
[Firestoreから削除]
    │   - deleteDocument(documentId)
    │
    ▼
[ローカル状態を更新]
```

### 3.2 フォルダ管理

#### 操作一覧

| 操作 | 関数 | 備考 |
|------|------|------|
| 作成 | `createFolder(userId, companyId, name)` | 空文字列は不可 |
| 更新 | `updateFolder(folderId, name)` | 名前のみ変更可 |
| 削除 | `deleteFolder(folderId)` | ドキュメントが存在する場合は削除不可 |
| 選択 | `setSelectedFolderId(id)` | nullで「すべて」表示 |

### 3.3 ナレッジ検索（チャット統合）

#### 3.3.1 検索フロー

```
[ユーザーがメッセージ送信]
    │
    ▼
[1] 検索クエリ生成
    │   generateSearchQuery(apiKey, question, history)
    │   ├── ユーザーの意図を分析
    │   ├── 指示語を具体的な言葉に置換
    │   └── 複数の検索クエリを生成（Multi-Query）
    │
    ▼
[2] ナレッジ検索実行
    │   advancedKnowledgeSearch(apiKey, storeNames, question, queries)
    │   ├── 複数クエリで並列検索
    │   ├── 重複除去（deduplicateCitations）
    │   └── 再ランキング（rerankResults）
    │
    ▼
[3] 検索結果をコンテキストに統合
    │   - 上位5件の引用を抽出
    │   - ドキュメント情報マップで表示名を変換
    │
    ▼
[4] AI応答生成
    │   - システムプロンプトに検索結果を含める
    │
    ▼
[5] メッセージと引用を保存・表示
```

#### 3.3.2 検索クエリ生成（generateSearchQuery）

**入力:**
- `apiKey`: Gemini APIキー
- `userQuestion`: ユーザーの質問
- `conversationHistory`: 会話履歴（指示語解決用）

**出力:**
```typescript
{
  query: string        // メイン検索クエリ
  queries: string[]    // 複数の検索クエリ（3件程度）
  error: string | null
}
```

**内部処理:**
1. 会話履歴から「それ」「この」などの指示語を解決
2. 専門用語と一般用語の両方を抽出
3. HyDE（Hypothetical Document Embeddings）で仮想回答を生成
4. 複数の観点から検索クエリを生成

#### 3.3.3 高度な検索（advancedKnowledgeSearch）

**入力:**
- `apiKey`: Gemini APIキー
- `storeNames`: 検索対象ストア名の配列（最大5件）
- `originalQuestion`: 元の質問
- `queries`: 検索クエリ配列

**出力:**
```typescript
{
  citations: Citation[]  // 引用情報（上位5件）
  error: string | null
}
```

**処理:**
1. 各クエリでFile Searchを並列実行
2. 結果をマージ
3. 重複除去（テキストの先頭100文字で判定）
4. 再ランキング（Geminiで関連性を再評価）
5. 上位5件を返却

## 4. 必須API関数

### 4.1 Gemini File Search関連

| 関数 | 役割 | 引数 | 戻り値 |

## 6. 状態管理

### 6.1 必須の状態

```typescript
// データ
documents: KnowledgeDocument[]        // ドキュメント一覧
folders: KnowledgeFolder[]            // フォルダ一覧
stores: FileSearchStore[]             // ストア一覧
selectedFolderId: string | null       // 選択中フォルダ

// UI状態
loading: boolean                      // 初期ロード中
uploading: boolean                    // アップロード中
error: string | null                  // エラーメッセージ
processingStatus: ProcessingStatus    // 各ファイルの処理状態

// 外部連携
companyDriveConnection: object | null // Google Drive接続情報
```

### 6.2 計算される状態

```typescript
// フィルタリングされたドキュメント
filteredDocuments = selectedFolderId
  ? documents.filter(d => d.folderId === selectedFolderId)
  : documents

// 各フォルダのドキュメント数
folderDocumentCounts = folders.map(folder => ({
  folderId: folder.id,
  count: documents.filter(d => d.folderId === folder.id).length
}))
```

## 7. エラーハンドリング

### 7.1 エラー種別と対応

| エラー種別 | 対応 |
|-----------|------|
| アップロード失敗 | 該当ファイルをerror状態にし、他ファイルは継続 |
| Gemini API エラー | エラーログを記録、ユーザーにメッセージ表示 |
| Firestore エラー | 状態をロールバック、エラーメッセージ表示 |
| 削除失敗 | エラーメッセージ表示、状態を元に戻す |
| フォルダ削除（ドキュメントあり） | 削除不可メッセージを表示 |

### 7.2 バリデーション

| 項目 | ルール |
|------|--------|
| フォルダ名 | 空文字列不可、trim()適用 |
| ファイル形式 | 対応形式のみ受付 |
| ストア数 | 最大5件（Gemini API制限） |

## 8. チャット統合の実装ポイント

### 8.1 初期化時に必要な処理

1. `getCompanyFileSearchStores(companyId)` でストア一覧取得
2. `getDocuments(companyId)` でドキュメント一覧取得
3. `documentInfoMap` を構築（geminiFileName → 表示情報のマップ）

### 8.2 メッセージ送信時の処理

1. ナレッジ検索が有効かチェック（`enabledTools.includes('knowledge_search')`）
2. ストアが存在するかチェック（`fileSearchStores.length > 0`）
3. `generateSearchQuery()` でクエリ生成
4. `advancedKnowledgeSearch()` で検索実行
5. 結果をシステムプロンプトに追加
6. AI応答と引用情報を保存

### 8.3 引用表示

```typescript
// 引用情報の構造
{
  title: "ドキュメント名.pdf",  // originalFileNameを使用
  uri: "https://...",          // fileUrlを使用
  text: "引用テキスト...",
  source: "knowledge"
}
```
